# 2025-26 시즌 추가 파일럿 (보류 상태)

`data/player.xlsx`는 2024-25 시즌까지만 있다. 2025-26 시즌을 추가할 수 있는지
검증한 파일럿 기록이다 — 사용자 요청으로 전체 실행은 보류하고, 검증 결과와
스크립트만 남겨둔다.

## 결론
- FotMob 사이트가 재설계되어 기존 `ml/data_pipeline/scrape_fotmob.py`(선수
  개별 페이지의 "90분당" 버튼 클릭 방식)는 더 이상 작동하지 않는다 (CSS 클래스가
  전부 바뀜).
- 대체 방법 2가지를 찾아서 둘 다 검증했다:
  1. **리그 전체 랭킹 페이지** (`pl_2025_26_leaderboard_*.json`): 스탯
     카테고리 18개 페이지만 긁으면 리그 전체 선수(537명)를 몇 분 안에 얻을 수
     있다. 다만 원본 31개 스탯 중 **17개만** 대응되는 카테고리가 있다.
  2. **선수 개별 페이지 + 90분당 토글** (`scrape_player_stats_per90.py`):
     기존 스크래퍼와 똑같은 방식인데 CSS 선택자만 새로 짠 것. 원본 31개 중
     **24~27개**까지 커버되고 단위도 기존 데이터와 완전히 일치함을 확인했다
     (예: Haaland 득점 — 기존 2024-25: 0.72, 신규 2025-26: 0.82, 같은 스케일).
     대신 선수 수만큼 페이지를 방문해야 해서 느리다 (리그 하나에 30~45분
     추정, 5개 리그면 3~4시간).

## 파일 설명
- `pl_2025_26_leaderboard_raw.json`: 방법 1로 긁은 원본 값 (단위 혼재 — 득점/
  어시스트/카드/페널티는 시즌 누적, 나머지는 이미 90분당).
- `pl_2025_26_leaderboard_per90.json`: 위 데이터를 전부 90분당으로 통일하고
  90분 미만 출전자를 제외한 최종본 (475명, 17개 스탯).
- `scrape_player_stats_per90.py`: 방법 2 (더 완전한 버전)의 재사용 가능한
  스크립트. 실행하면 리그 하나를 끝까지 스크래핑한다. **아직 전체 실행은
  안 했다** — Haaland 1명으로 접근 방식만 검증된 상태다.

## 남은 작업 (진행하기로 하면)
1. `scrape_player_stats_per90.py`를 5개 리그에 대해 실행 (오래 걸림, 체크포인트
   저장 있음).
2. 신규/루키 선수는 `ml/data_pipeline/match_transfermarkt_ids.py`로 Transfermarkt
   ID 매칭.
3. `ml/data_pipeline/fetch_market_values.py`로 2025-26 시장가치 조회.
4. `data/player.xlsx`에 Season="2025-2026"으로 병합.
5. `python ml/train.py`로 재학습 (포지션 통합 모델이라 전체 재학습 필요).
