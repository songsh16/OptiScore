# 모델 평가 리포트

`ml/train.py` 실행 결과 (재현 가능, `python ml/train.py`로 동일 결과 재생산). 원자료는
`ml/reports/results.json`, 하이퍼파라미터 재탐색 원자료는 `ml/reports/best_params.json`.

## 0. 성능 개선 전체 요약

4단계를 거쳐 "정직하게 측정한" R²를 평균 **66.0% → 72.2%** (+6.2%p)까지 끌어올렸다.
가장 크게 개선된 포지션은 윙어(+12.7%p), 측면 수비수(+9.0%p), 측면 미드필더(+9.8%p).

| 포지션 | ① 데이터 누수 수정 직후 | ② + 새 피처 | ③ + 하이퍼파라미터 재탐색 (최종) | 최종 모델 |
|---|---|---|---|---|
| 공격형 미드필더 | 77.4% | 81.2% | **80.4%** | XGBoost |
| 수비형 미드필더 | 66.8% | 69.5% | **71.1%** | XGBoost |
| 스트라이커 | 67.4% | 69.7% | **70.4%** | XGBoost |
| 윙어 | 62.1% | 69.1% | **74.8%** | XGBoost |
| 중앙 미드필더 | 69.1% | 73.5% | **73.6%** | XGBoost |
| 중앙 수비수 | 76.8% | 79.4% | **79.9%** | XGBoost |
| 측면 미드필더 | 40.3% | 42.4% | **50.1%** | LightGBM |
| 측면 수비수 | 67.9% | 75.0% | **76.9%** | LightGBM |
| **평균** | **66.0%** | **71.2%** | **72.2%** | |

①은 지난 라운드에서 데이터 누수(랜덤 train/test 분할)만 고친 시점의 수치 — 자세한 내용은
아래 4절. 여기서부터가 이번 라운드에서 실제로 손댄 부분이다.

## 1. 새 피처 3종 (① → ②)

기존 47개 피처에 아래 3종을 추가했다 (`backend/features.py`). 학습(`ml/train.py`)과
서빙(`backend/app.py`)이 동일 함수(`engineer_batch`/`engineer_single`)를 쓰므로
피처 정의가 어긋날 일이 없다.

1. **리그 원-핫 (5개 컬럼)**: 같은 스탯이라도 리그에 따라 시장가치 수준이 체계적으로
   다르다 (특히 프리미어리그의 "재정 프리미엄"). 실제로 `리그_Premier League`가
   대부분 포지션에서 상위 5~8위 피처로 들어갔다 (3절 참고).
2. **커리어 시즌차수**: 이 선수가 데이터셋에서 몇 번째 시즌인지 (나이와는 별개로
   "얼마나 검증됐는가"를 나타내는 신호).
3. **2시즌 이동평균** (변화량 대상 8개 스탯): 단일 시즌 변화량은 노이즈가 크다.
   득점/어시스트/터치 등 핵심 스탯의 최근 2시즌 평균을 추가해 트렌드를 더 안정적으로
   반영했다. 데뷔 시즌(직전 시즌 없음)은 이번 시즌 값 자체를 평균으로 사용한다.

이 3종만 추가하고 하이퍼파라미터는 그대로 둔 상태로 재검증한 게 ②번 컬럼이다.
8개 포지션 전부 개선됐다.

## 2. 정직한 하이퍼파라미터 재탐색 (② → ③)

기존 하이퍼파라미터(`ml/train.py`의 `LEGACY_XGB_PARAMS`)는 `max_depth`가 최대 19까지
올라가는 등, 원래 프로젝트에서 데이터 누수가 있던 랜덤 분할 기준으로 튜닝됐을
가능성이 컸다. `ml/tune.py`로 **선수 단위 `GroupKFold`(4-fold) 교차검증 점수**를
목적함수로 삼아 Optuna로 재탐색했다 (포지션당 40 trials × XGBoost/LightGBM 각각):

- 탐색 공간을 `max_depth 3~8`로 제한해 애초에 극단적으로 깊은 트리가 나오지 않게 함
- `n_estimators 300~1000` + `early_stopping_rounds=50`으로 실제 트리 수는 자동 결정
- `min_child_weight`/`min_samples` 등 정규화 파라미터도 함께 탐색
- XGBoost와 LightGBM을 동일 조건으로 비교해서, 포지션별로 **CV R²가 더 높은 쪽을
  최종 모델로 채택** (측면 미드필더·측면 수비수는 LightGBM이 근소하게 더 좋았음)

| 포지션 | XGBoost CV R² | LightGBM CV R² | 채택 |
|---|---|---|---|
| 공격형 미드필더 | **75.7%** | 75.6% | XGBoost |
| 수비형 미드필더 | **76.9%** | 76.5% | XGBoost |
| 스트라이커 | **78.2%** | 77.8% | XGBoost |
| 윙어 | **72.4%** | 71.6% | XGBoost |
| 중앙 미드필더 | **76.9%** | 76.3% | XGBoost |
| 중앙 수비수 | **79.2%** | 78.6% | XGBoost |
| 측면 미드필더 | 42.0% | **45.8%** | LightGBM |
| 측면 수비수 | 74.0% | **74.2%** | LightGBM |

XGBoost가 대체로 근소하게 앞섰지만, 표본이 가장 적은 두 포지션(측면 미드필더·측면
수비수)에서는 LightGBM의 리프 단위 분할(leaf-wise growth)이 더 유리했던 것으로 보인다.

나와, 노이즈를 줄이는 효과가 있었다는 가설을 뒷받침한다.

## 5. 데이터 누수 수정 (지난 라운드 요약)

기존 `train_test_split`은 완전 랜덤이라 같은 선수의 여러 시즌이 train/test에 걸쳐
섞였다. `GroupShuffleSplit(groups=선수명)`으로 선수 단위 분할로 바꿔 재검증한 결과가
위 표의 ①번 컬럼이다. 자세한 전/후 비교는 git 히스토리의 이전 버전 리포트 참고.

## 6. 알려진 한계
1. **측면 미드필더**는 표본이 356건(162명)으로 가장 적어, 50.1%까지 끌어올렸어도
   다른 포지션 대비 여전히 낮다. 근본적으로는 더 많은 데이터가 필요하다.
2. **슈퍼스타 과소평가**는 피처/모델을 개선해도 해결되지 않는 구조적 한계다 (4절).
3. **커리어 시즌차수·2시즌평균의 실시간 예측(what-if) 근사**: `/api/predict`는 실제
   커리어 이력을 모르므로, `prev_stats`가 주어지면 "2년차 이상"으로 근사한다. 배치
   학습(`ml/train.py`)에서는 정확한 값을 쓰지만, 실시간 예측에서는 근사치임을
   감안해야 한다.
4. **여전히 선수 단위 그룹 분할**: 실제 배포 시나리오(과거 시즌으로 학습해 미래
   시즌을 예측)보다는 관대한 검증이다. 시즌 기준 시간 분할이 다음 단계로 더 적합.
5. **앙상블은 시도했지만 채택하지 않았다**: XGBoost·LightGBM 예측을 단순 평균하는
   앙상블을 held-out 테스트셋에서 실제로 비교했다. 8개 포지션 중 5개(공격형 미드필더,
   수비형 미드필더, 윙어, 측면 미드필더, 측면 수비수)에서 단일 모델보다 근소하게
   좋았지만(최대 +0.9%p, 측면 미드필더), 나머지 3개(스트라이커, 중앙 미드필더,
   중앙 수비수)에서는 오히려 더 나빴다. 이득이 작고 포지션마다 일관되지 않는 데 비해
   모델 2개를 항상 같이 서빙해야 하는 복잡도가 커서, 이번엔 포지션별 단일 최고
   모델(XGBoost 또는 LightGBM)만 채택했다.
