# OptiScore — 축구 선수 시장 가치 예측 서비스

유럽 5대 리그 선수의 시즌 경기 기록으로 **Transfermarkt 시장 가치를 예측**하는 웹 서비스입니다.
데이터 수집(크롤링) → 피처 엔지니어링 → 모델 학습·검증 → Flask API → 웹 프런트엔드까지
전 과정을 개인 프로젝트로 구현했습니다.

| 항목 | 내용 |
|---|---|
| 데이터 | 5대 리그 필드 플레이어 11,637건 (선수×시즌), 2016-17 ~ 2024-25 시즌 |
| 모델 | 포지션을 피처로 받는 단일 XGBoost 회귀 모델 (피처 68개) |
| 성능 | 선수 단위 GroupKFold 교차검증 R² **77.3%** (8개 포지션 평균) |
| 서비스 | 선수 검색·상세, 시장 가치 what-if 예측, 회원가입/로그인, 즐겨찾기 |
| 스택 | Python · pandas · XGBoost · scikit-learn · Optuna · Flask · SQLite · HTML/CSS/JS |

---

## 1. 프로젝트 배경

선수의 가치 평가는 여전히 감독·스카우터의 주관적 판단에 크게 의존하고, 기존 데이터 기반 접근은
xG·패스 성공률처럼 **특정 지표 하나에 치우치는 경우**가 많습니다. 그래서 "경험적으로 좋은 선수인데
데이터로는 평범해 보이는" 괴리가 생깁니다.

OptiScore는 득점·패스·수비·볼 소유 등 **다양한 시즌 기록을 통합해서** 선수의 시장 가치를
설명·예측하는 것을 목표로 했습니다. 기존 통계 사이트(FBREF 등)는 정보가 한 화면에 과도하게 몰려
있어 탐색이 어렵다는 점도 문제로 보고, **검색 중심의 단순한 화면**으로 결과를 보여주는 웹 서비스까지
만들었습니다.

## 2. 주요 기능

- **선수 검색 / 상세 정보**: 이름 자동완성 검색, 포지션·생년월일·현재 시장 가치와 모델 예측값 비교
- **What-if 시장 가치 예측**: 포지션·리그·나이·작년 시장 가치와 이번 시즌(선택적으로 지난 시즌) 스탯을
  입력하면 예상 시장 가치를 계산. 사용자는 원본 스탯만 입력하고, 파생 피처는 서버가 계산합니다.
- **회원 기능**: 회원가입 / 로그인(bcrypt 해시, 세션) / 관심 선수 즐겨찾기 / 프로필

## 3. 시스템 구조

```
[FotMob]  ──Selenium──▶  시즌별 90분당 스탯 ─┐
[Transfermarkt] ──API──▶ 선수 ID · 시장 가치 ─┴─▶ data/player.xlsx (11,637건)
                                                      │
                                   ml/train.py ◀──────┘   (backend/features.py 공유)
                                        │
                                        ▼
frontend/ (HTML/CSS/JS) ──fetch──▶ backend/app.py (Flask) ──▶ backend/models/model_bundle.pkl
                                        └──▶ SQLite (회원·즐겨찾기)
```

학습(`ml/train.py`)과 서빙(`backend/app.py`)이 **같은 피처 엔지니어링 모듈**(`backend/features.py`)을
사용합니다. 그래서 학습 때와 예측 때 피처 정의가 어긋날 수 없습니다.

## 4. 데이터

| 단계 | 내용 | 코드 |
|---|---|---|
| 스탯 수집 | FotMob 리그별 통계 페이지를 Selenium으로 순회하며 선수별 90분당 스탯 수집 | `ml/data_pipeline/scrape_fotmob.py` |
| ID 매칭 | FotMob 선수명으로 Transfermarkt 검색 → 선수 ID 매칭 | `ml/data_pipeline/match_transfermarkt_ids.py` |
| 시장 가치 | Transfermarkt 시장 가치 변동 이력을 시즌 단위로 정리 | `ml/data_pipeline/fetch_market_values.py` |

- 출전 시간에 관계없이 공정하게 비교하도록 **90분당 기록**을 사용했습니다.
- 세부 포지션(오른쪽 윙어, 왼쪽 수비수 등)은 8개 그룹으로 묶었습니다:
  스트라이커 · 윙어 · 공격형/중앙/수비형/측면 미드필더 · 중앙/측면 수비수
- 컬럼 설명은 [`data/README.md`](data/README.md)에 정리했습니다.

## 5. 모델링

### 피처 엔지니어링 (68개)
| 분류 | 피처 | 의도 |
|---|---|---|
| 원본 스탯 | 득점, 어시스트, 슛, 패스, 태클, 터치 등 31개 | 시즌 퍼포먼스 |
| 가치 이력 | `log(작년 시장 가치)` | 시장 가치의 강한 자기상관 |
| 나이 | 나이, 나이² | 전성기를 정점으로 하는 비선형 노화 곡선 |
| 추세 | 핵심 스탯 8개의 전 시즌 대비 변화량, 2시즌 이동평균 | 성장/하락세, 단일 시즌 노이즈 완화 |
| 커리어 | 커리어 시즌차수 | 나이와 별개로 리그에서 검증된 정도 |
| 맥락 | 리그 원-핫, 포지션 원-핫 | 리그별 재정 프리미엄, 포지션별 가치 차이 |

타깃은 오른쪽으로 크게 치우친 시장 가치 분포를 고려해 `log1p(시장 가치)`로 학습했습니다.

### 검증 설계 — "같은 선수"가 train/test에 섞이지 않게
같은 선수의 여러 시즌이 데이터에 함께 있습니다. 행 단위로 랜덤 분할하면, 메시의 2021 시즌으로 학습하고
2022 시즌으로 평가하는 식의 **데이터 누수**가 생깁니다. 그래서 모든 평가를 **선수 단위
`GroupKFold`(4-fold)** 로 했습니다. 처음 보는 선수에 대한 성능을 재기 위해서입니다.
조기 종료(early stopping)에 쓰는 검증 세트도 선수 단위로 나눴습니다.

### 성능 개선 과정
| 단계 | 변경 | 평균 R² |
|---|---|---|
| 1 | 데이터 누수 제거 (선수 단위 분할) | 66.0% ¹ |
| 2 | 리그 원-핫 · 커리어 시즌차수 · 2시즌 이동평균 피처 추가 | 71.2% ¹ |
| 3 | GroupKFold 기준 Optuna 하이퍼파라미터 재탐색, 포지션별 XGBoost/LightGBM 선택 | 71.8% ² |
| 4 | **포지션별 모델 8개 → 포지션을 피처로 넣은 통합 모델 1개** | **77.3%** ² |

¹ 단일 그룹 분할 기준 &nbsp; ² 4-fold GroupKFold 평균 (최종 공식 지표)

### 포지션별 최종 성능 (GroupKFold 4-fold 평균)
| 포지션 | 표본 | R² |
|---|---|---|
| 스트라이커 | 1,767 | 80.9% |
| 공격형 미드필더 | 1,012 | 80.6% |
| 중앙 수비수 | 2,511 | 80.4% |
| 수비형 미드필더 | 1,381 | 80.1% |
| 중앙 미드필더 | 1,455 | 79.8% |
| 측면 수비수 | 1,806 | 77.0% |
| 윙어 | 1,362 | 74.5% |
| 측면 미드필더 | 343 | 65.1% |

중요도 상위 피처는 `log(작년 시장 가치)`(18.3%), `리그_Premier League`(11.0%), 나이(6.3%),
나이²(6.0%), 성공한 패스·득점의 2시즌 평균 순이었습니다. "같은 스탯이면 프리미어리그 선수가 더
비싸다"는 가설이 실제로 강한 신호로 확인됐습니다.

## 6. 기술적 도전과 해결

**① 랜덤 분할이 성능을 부풀리고 있었다**
처음 버전은 `train_test_split`을 행 단위로 랜덤하게 했습니다. 선수 단위 분할로 바꿔 다시 재 보니
8개 중 6개 포지션의 R²가 실제보다 높게 나와 있었습니다(예: 윙어 75.2% → 62.1%). 이후 모든 실험을
선수 단위 분할 기준으로 다시 했습니다.

**② 단일 분할 하나로는 작은 그룹의 성능을 믿을 수 없었다**
측면 미드필더(343건)는 `random_state`만 바꿔도 R²가 **4% ~ 56%** 사이를 오갔습니다. 그래서 공식
지표를 단일 분할에서 GroupKFold 4-fold 평균으로 바꿨습니다. 표준편차도 함께 기록해, 다른 포지션은
±1~4%p인 반면 측면 미드필더만 ±17%p라는 점을 드러냈습니다.

**③ 표본이 적은 포지션 → 통합 모델로 해결**
처음에는 "다른 포지션 선수가 라벨만 잘못 붙어 섞였다"는 가설로 라벨을 정리했습니다. 하지만 해당 선수는
162명 중 9명뿐이었고 성능도 변하지 않았습니다. 근본 원인은 표본 부족이었습니다. 포지션마다 모델을
따로 두는 대신 **포지션을 피처로 넣은 모델 하나**로 합치자, 작은 포지션도 전체 데이터의 나이 곡선·리그
효과를 공유받아 **8개 포지션 전부** 좋아졌습니다(측면 미드필더 44.3% → 65.1%, 평균 71.8% → 77.3%).

**④ 학습과 서빙의 불일치 제거**
초기 코드는 학습과 예측의 피처 계산이 따로 손으로 작성되어 있었습니다. 그래서 `'태클'` vs `'태클 성공'`
같은 오타로 특정 피처가 예측 시 항상 0이 되는 문제가 있었습니다. 또한 학습 루프의 마지막 포지션 모델만
저장되고, 학습에 쓴 스케일러가 저장되지 않는 문제도 있었습니다. 피처 계산을 `backend/features.py` 하나로
합치고 모델 번들 저장 방식을 정리해 해결했습니다. XGBoost는 스케일링이 필요 없어 스케일러 자체를
없앴습니다.

**⑤ 사용자가 입력할 수 없는 예측 폼**
처음 예측 화면은 `log_전시즌_시장가치`, `나이_제곱` 같은 내부 피처명을 그대로 입력받았습니다.
사용자는 원본 스탯만 입력하고 서버가 파생 피처를 계산하도록 API와 화면을 다시 설계했습니다.

## 7. 시도했지만 채택하지 않은 것

| 시도 | 결과 | 판단 |
|---|---|---|
| XGBoost + LightGBM 단순 평균 앙상블 | 5개 포지션 소폭 개선, 3개 포지션 악화 | 이득이 작고 일관되지 않음 |
| AutoGluon (CatBoost·신경망 포함 AutoML) | 통합 XGBoost 대비 +0.8%p | 무거운 의존성·배포 복잡도 대비 이득 작음 |
| 측면 미드필더 라벨 정리 | CV R² 45.8% → 44.3% (오차 범위 내) | 근본 원인이 아님 (코드에는 유지) |
| 계약 잔여 기간 피처 | 공개된 과거 시점 계약 데이터 없음 | 수집 불가 |

## 8. 한계와 다음 단계

- **슈퍼스타 과소평가**: 시즌 스탯만으로는 브랜드 가치·이적시장 기대감을 설명하지 못합니다.
  그래서 케인·손흥민·사카 같은 선수는 꾸준히 낮게 예측됩니다. 다음 단계로 뉴스·검색량 같은 관심도
  신호를 생각하고 있습니다.
- **측면 미드필더**는 표본이 343건으로 적어 다른 포지션보다 성능이 낮습니다(65.1%).
- **극단값 외삽 불가**: 학습 데이터에 없는 가상 선수 100명으로 테스트한 결과, 나이·리그·작년
  시장 가치 효과는 기대한 방향으로 움직였습니다. 다만 트리 모델 특성상 시즌 20골을 넘으면 예측값이 더
  오르지 않고, 부상일수의 영향도 거의 없었습니다.
- **검증 방식**: 하이퍼파라미터 탐색과 성능 평가가 같은 분할을 써서 77.3%는 약간 낙관적일 수 있습니다.
  nested CV와 시간 순서 분할(과거 시즌으로 학습 → 최신 시즌 예측)로 더 엄격하게 검증할 계획입니다.
- **데이터 갱신**: 2024-25 시즌까지 반영되어 있습니다. FotMob 사이트가 개편되어 2025-26 시즌을
  수집하려면 스크래퍼를 다시 작성해야 합니다.

## 9. 실행 방법

```bash
pip install -r requirements.txt

# (선택) 모델 재학습 — 학습된 모델은 backend/models/model_bundle.pkl에 이미 포함
python ml/train.py

cd backend
python app.py
# http://127.0.0.1:5000
```

- 세션 서명 키는 환경변수 `OPTISCORE_SECRET_KEY`로 지정합니다 ([`.env.example`](.env.example) 참고).
- 하이퍼파라미터 재탐색: `python ml/tune_pooled.py --trials 40` (수십 분 소요, 결과는
  `ml/reports/best_params_pooled.json`에 포함)

